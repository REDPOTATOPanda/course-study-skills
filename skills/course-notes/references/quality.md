# Content Verification and Optional Collaboration

## Classify gaps

Record findings in the existing internal coverage inventory instead of creating duplicate ledgers:
- Missing: Knowledge, conditions, original-figure information, or examples within the confirmed scope were omitted.
- Under-explained: A conclusion exists but lacks assumptions, conceptual connections, or key derivations needed for this task.
- Incorrect or misplaced: Problems in notation, calculation, wording, or chapter placement.
- Ask the user: Conflicting/unreadable materials, missing answers, or supplementation that would change the authorized scope.

Finding a problem does not authorize expansion or answer changes. Recheck original materials first, then act within content-editing permissions. Ask the user together about unresolved substantive issues and continue unaffected work. Do not count knowledge absent from the source as an omission. Keep internal ledgers and unresolved markers out of final deliverables.

## Check coverage against existing questions

Use existing questions to check notes only when the task includes example verification, homework support, or an explicitly requested coverage check. Do not turn everyday notes into an exam guide by default. Preserve confirmed example treatment; screenshot-preservation mode does not automatically add solution reasoning.

Use only questions actually obtained and within the confirmed scope. Map their required concepts, conditions, and methods to draft locations and check whether the material supports complete answers. Distinguish source gaps, insufficient explanation, and out-of-scope material. Repeated occurrence does not establish that a question will appear on the exam. This check does not authorize predicted questions, rewritten examples, or newly supplied answers. Skip it if no suitable questions exist; do not force a match. Keep mappings internal.

## Verify calculable content

Where needed, cross-check values, probabilities, matrix dimensions, convolution output sizes, algorithm results, and other computations affecting understanding or answers using small calculations or independent derivations. Check inputs, units, boundary conditions, and rounding conventions. Do not require programming for every formula or introduce unrelated exercises. A numeric result from code does not prove a formula's assumptions. If verification disagrees with an original answer, revisit the original question and apply existing correction permissions; ask about substantive doubts. Do not claim verification without actually executing the calculation or derivation.

## Accept against concrete checks

Use the entrypoint's existing acceptance process. Turn issues into observable checks, such as whether key conditions remain, questions match answers, the contents page locates topics, original figures are complete, indices are obscured, or same-level styles agree. Check only items relevant to this task's scope and format. Recheck affected locations and related references after revisions. Do not invent self-assessment scores or substitute scoring for correction. Distinguish content verification, static inspection, and actual rendering; do not insert audit reports into the body.

## Use subagents only as needed

For long materials with independently processable chapters, figure checks, or review tasks, subagents may be used when the environment supports and permits delegation. Handle short documents, tightly coupled work, or unsupported environments with the main agent; multiple agents are not a mandatory step.

The main agent owns scope, global structure, terminology, and final integration. Delegate with necessary original materials, clear boundaries, format conventions, and separate output paths. Do not let multiple agents edit the same file simultaneously or send unrelated chats or entire material collections. Subagents return artifact paths, processed scope, key conventions, doubts, and actual checks performed. The main agent must read the integrated result and check cross-chapter connections and key facts; a completion summary alone is insufficient for delivery. Subagents must not expand scope or resolve unconfirmed user choices unilaterally. Do not promise lower total tokens or cost without comparative measurement.
